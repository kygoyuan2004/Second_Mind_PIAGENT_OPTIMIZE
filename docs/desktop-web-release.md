# Desktop and Docker Web validation

For Pi v0.3.0, the release branch builds all five desktop files. The tagged workflow publishes the tested Docker digest, exercises both editions through anonymous pulls, and prepares a draft with SHA-256 checksums. Once the owner has checked the draft on a MacBook and approved publication, fast-forwarding `main` to the exact verified tag publishes the draft. The publication job rechecks the successful tag run, all five filenames and the downloaded bytes.

On a MacBook, download the Apple Silicon DMG from the draft in a browser. Match its SHA-256 and confirm the downloaded file carries the quarantine attribute before following the [first launch instructions](macos-desktop.md). Save a model connection, reopen the app, then ask a question about a three-line sample note and open its source citation. Record the macOS version, app version, reported source line, and whether the saved connection worked after reopening. Keep keys and personal notes out of the report.

## Claude SDK v0.2.1 observations

The following observations were recorded for the Claude SDK v0.2.1 release. For Pi desktop packages see the [v0.3.0 release notes](release-notes-0.3.0.md). The v0.2.1 desktop and web apps used one backend and UI with Claude Agent SDK 0.3.247. Windows packages use an NSIS per-user installer. Linux x86_64 packages include a private Node, Python, FFmpeg and media dependencies built from the same Docker runtime. A Linux desktop session and an unlocked Secret Service keyring are required to persist a desktop credential. The speech model downloads on first use. An existing Qwen ASR installation can be selected on a GPU server with the absolute paths in `KNOWLEDGE_ASR_PYTHON` and `KNOWLEDGE_ASR_MODEL_DIR`. Set `KNOWLEDGE_ASR_ALIGNER_DIR` for timestamped video when its location differs from the model's sibling directory.

Use the desktop setup for a local Vault or a separate HTTPS server connection. Use the Docker setup to host the web workspace. Select a knowledge base before generating a draft. The plan editor previews dated items with explicit start and end times. Confirmation writes the Markdown and records the scheduled entries with a retry receipt. The daily view checks per-event revisions before saving edits.

| Check | Environment and observed result |
|---|---|
| Models | Real SDK checks on an isolated Linux server using public notes. Bailian, DeepSeek, Kimi and a custom connection to DeepSeek each produced two consecutive answers. Private credentials were entered in the application settings and retained across a restart. |
| Search and evidence | A DeepSeek learning review linked back to the highlighted original paragraph. A web-enabled question made a Tavily search and returned two official documentation pages that both responded with HTTP 200. The offline sessions made no Tavily calls. |
| Audio and video | A public audio fixture produced text with the optional GPU Qwen ASR engine. The container also transcribed audio with CPU Whisper, processed video frames and generated a confirmable video draft using the real SDK with a simulated model response. |
| Plan | Two reviewed items were saved to the demonstration Vault and opened in the daily schedule. Automated API checks also exercised repeat confirmation, receipt replay after restart, stale edits and knowledge-base selection. |
| Linux desktop | The x86_64 AppImage and unpacked Debian payload both launched on Ubuntu 24.10 with a private Secret Service session. The real system keyring, a Chinese Vault path and isolated remote connections passed. The Debian package installed, reinstalled and uninstalled in a disposable Debian environment. |
| Windows desktop | Windows 11 Home x64 build 26200 ran the native filesystem, media, Electron and DPAPI checks. In the Windows desktop UI, a real DeepSeek connection read a local demonstration Vault containing a cache junction, then a separate temporary Linux server Vault. Each answer returned its own note's unique identifier and a source citation. The desktop switched back to local mode. The Windows Server 2022 CI job installs, upgrades and removes the installer. Windows 10 x64 client installation remains unverified. |
| Docker Web | Linux amd64 install, restart, update, backup, separate restore and uninstall passed with a synthetic Vault. A separate old/new/old/new image rehearsal retained settings and the configuration URL. Windows/macOS Docker Desktop host lifecycles remain unverified. |

Desktop and Web installations keep their state outside the selected Vault. Preserve both the Vault and the application state when making backups. Keep your previous installer and the backup made before upgrading. The Windows uninstall flow normally preserves user data. Linux package removal leaves the Vault and per-user desktop state in place.
